### 2.2 T=2.0 Temperature-Scaled Sampling

**Primary training indices.** Temperature-scaled sampling (T=2.0) reweights multi-dataset batches to prevent the dominant dataset (LIDC: 243K slices) from drowning out smaller ones. LIDC is downsampled; smaller datasets are upsampled via repetition. Total slices are identical to raw, but per-dataset sampling probabilities are balanced.

## 4. Data Pipeline (DICOM → Training Tensor)

```
Raw DICOM / NIfTI volumes
    │
    ▼
scripts/preprocessing/phase2_preprocess_lidc_idri.py   ← DICOM → 16-bit HU PNG
scripts/preprocessing/phase2_preprocess_nifti.py        ← NIfTI → 16-bit HU PNG
scripts/preprocessing/extract_dicom_spacing.py          ← DICOM header → spacing metadata
    │
    ▼
/mnt/nas-ai-models/training-data/dino-x/{dataset}/processed-hu16/
    ├── {series_dir}/
    │   ├── slice_0000.png     ← 16-bit PNG, HU encoded as u16 = round(HU*10) + 32768
    │   ├── slice_0001.png
    │   └── ...
    └── _index/index.csv       ← per-slice index with spacing metadata
    │
    ▼
scripts/preprocessing/mvp_combine_indices.py
    │
    ▼
data/mvp/combined_*dataset*.csv     ← Training index CSV
data/mvp/split_manifest_*.json      ← Train/val series-level splits
    │
    ▼
zoo/manifest.py                     ← Parquet manifest (SliceMetadata records)
zoo/data.py (ManifestDataset)       ← PyTorch Dataset: 2.5D stacking + random windowing
    │
    ▼
(B, 3, H, W) tensor + (B, 3) spacing tensor → DINO training
```

**Key pipeline decisions:**
- HU values stored as `u16 = round(HU*10) + 32768` in uint16 PNG — one decimal of HU precision, decode `HU = (u16 − 32768) * 0.1`, encodable range ≈ [−3276.8, +3276.7] HU (clamped to avoid overflow)
- 2.5D stacking: 3 consecutive slices (z-1, z, z+1) as RGB-like channels
- Random HU windowing at training time: level in [-400, 400], width in [800, 2000]
- Scale embedding: `(spacing_x, spacing_y, slice_thickness)` from DICOM header, injected as continuous values via small MLP

## 8. Provenance Chain Per Run

Every training run in `runs/` freezes a `config.json` with:
- `git_commit`: exact commit SHA at launch
- `index_csv`: path to the data index used
- All CLI hyperparameters

The `zoo/lineage.py` module computes a deterministic data hash from the index CSV contents, ensuring reproducibility. Experiment provenance files in `experiments/dino-x-v1/` link arm slugs to git commits, data indices, and results.

**Rule AGENTS.md #6:** `git_commit` must be recorded at run start. Without a commit SHA, the experiment is not reproducible.
